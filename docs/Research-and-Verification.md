# Research and verification

## Evidence levels

1. **Imported source note:** preserved from the existing research. Its date and claimed verification are retained; it is not silently marked checked today.
2. **Official release metadata checked:** exact loader, Minecraft version and release ID checked at the primary source.
3. **Actual files/source inspected:** a named archive/revision was read. The study specifies which models, animations, scripts or classes were examined.
4. **Native tested:** a matching game/runtime test has recorded evidence. No imported recommendation inherits this status automatically.

## Identity and categories

Project routes, not display names or sheet ranks, are used for conservative duplicate reconciliation. Notes from repeated records are preserved. Ambiguous multi-project links, ports, forks and historical aliases stay reviewable. Search routes and built-in features are not counted as independent installable mods.

Categories describe gameplay purpose. Edition, loader, Minecraft version, ecosystem, resource pack/mod/library/tool type and evidence level are separate filters. Source sheet names do not determine wiki page titles.

## Keeping information current

Refresh exact primary-source releases for the relevant loader/version, preserve earlier notes, and record what changed. Do not assume a project-wide latest release supports every lane. An author changelog, community issue report and reproduced test are different evidence. No scheduled updater is claimed to have been created here.

## Keep published catalogue data fresh

Index and detail requests share a revision derived from the current data files. Refresh it when publishing changes, then verify search and detail views after deployment. A successful build alone does not prove returning visitors see the latest records.
